# 📋 نظام إدارة التقارير

نظام متكامل لإدارة التقارير الميدانية مع **مدير نظام** و**مستخدمي إدخال**، يتضمن:
لوحة تحكم بالإحصائيات، إدارة المستخدمين والصلاحيات، إدخال تقارير مع مسودات محلية ومزامنة
إلى قاعدة البيانات، تقييم المستخدمين، وتقييم التقارير مع تصفية وفرز وطباعة.

> الواجهة عربية بالكامل (RTL). التقارير تُحفظ محلياً كمسودات على جهاز المدخل،
> وعند الضغط على «حفظ وترحيل / مزامنة» تنتقل إلى قاعدة بيانات **SQLite** على جهاز
> مدير النظام ويُحذف التقرير من جهاز المدخل نهائياً.

---

## 🚀 التشغيل السريع

### المتطلبات
- **Node.js 22 أو أحدث** (مجاني من https://nodejs.org) — يُثبَّت مرة واحدة على **جهاز المدير** فقط.
- متصفح حديث (Chrome / Edge / Firefox) على جميع الأجهزة.

### التشغيل على جهاز المدير (الخادم)
| النظام | الطريقة |
|---|---|
| **Windows** | انقر نقراً مزدوجاً على `start-system.vbs` للتشغيل المخفي التلقائي |
| **Linux / macOS** | نفّذ `./run.sh` من الطرفية |

ثم افتح المتصفح على: **http://localhost/**. يستخدم النظام منفذ HTTP الأساسي **80**، لذلك لا حاجة لكتابة رقم منفذ.

يشغّل `start-system.vbs` الخادم في الخلفية ويفتح المتصفح تلقائياً. يحاول أولاً استخدام المنفذ 80، وإذا رفض Windows تشغيله ينتقل تلقائياً إلى المنفذ 8080 ويفتح العنوان الصحيح. لا يحتاج المستخدم إلى فتح موجّه الأوامر.

إذا لم يفتح النظام، راجع الملف `server.log` داخل مجلد `ReportsSystem` لمعرفة السبب، وتأكد من فتح `http://localhost/` وليس العنوان القديم الذي يحتوي على `:8765`.

> إذا كان المنفذ 80 مستخدماً أو لم تكن لديك صلاحية تشغيله، استخدم `PORT=8080 node server.js`، ثم افتح `http://localhost:8080/`.

### توصيل أجهزة الإدخال الأخرى (نفس شبكة الواي فاي)
1. في لوحة المدير ← **الإعدادات** سيجد المدير عنوان الشبكة (مثال: `http://192.168.1.5/`).
2. على كل جهاز إدخال، افتح المتصفح واكتب ذلك العنوان ثم سجّل الدخول بحساب المستخدم.
3. عندما يضغط المستخدم «حفظ وترحيل / مزامنة» تصل بياناته فوراً إلى قاعدة بيانات المدير.

## 🧩 الواجهات والميزات

### 1) لوحة التحكم (المدير)
- بطاقات إحصائيات: إجمالي التقارير، تقارير اليوم، المستخدمون، التقييمات، متوسط الموثوقية.
- توزيع تقييم التقارير (مهم جداً / مهم / متوسط / عادي / غير مهم).
- عدد تقارير كل مستخدم، وحالة المستخدمين (نشط / متقطع / غير نشط).
- أحدث التقارير وآخر التقييمات.

### 2) المستخدمون والصلاحيات (المدير)
- إضافة مستخدمين إدخال.
- منح **صلاحيات منفصلة**: فتح، إضافة، حذف، تعديل، طباعة.
- تفعيل/تعطيل الحساب، تغيير كلمة المرور، حذف المستخدم.
- **آلية منح الصلاحية في كل مرة**: عند تفعيل خيار «استهلاك صلاحية الإضافة بعد كل مزامنة»
  (مفعّل افتراضياً)، لا يستطيع المستخدم إدخال تقرير جديد إلا بعد أن يمنحه المدير
  صلاحية «إضافة» من جديد — تماماً كما هو مطلوب.

### 3) إدخال البيانات (مستخدم الإدخال)
الحقول: **رقم التقرير، موضوع التقرير، الجهة أو الشخص الذي عليه التقرير، التاريخ،
الوقت، المكان، حقل كبير للتقرير التفصيلي، إضافة أكثر من صورة،
اسم مُدخل التقرير (يُملأ تلقائياً من النظام)**.

- **💾 حفظ كمسودة**: يبقى التقرير معلقاً على جهاز المدخل، قابلاً للتعديل في أي وقت، ولا يراه المدير.
- يمكن للمستخدم إنشاء عدد غير محدود من التقارير ما دامت صلاحية الإضافة مفعلة؛ لا تُستهلك الصلاحية بعد المزامنة افتراضياً.
- **🚀 حفظ وترحيل / مزامنة**: ينقل التقرير إلى قاعدة بيانات المدير، **ويُحذف نهائياً من جهاز
  المدخل** ولا يمكن فتحه أو إعادة تحميله مرة أخرى.
- قائمة المسودات المحلية مع فتح/تعديل/حذف.

### 4) التقارير (المدير)
- عرض مختصر لكل تقرير: رقم التقرير، الموضوع، الجهة/الشخص، اسم المدخل، التاريخ، الصور.
- **حقل تقييم التقرير** (مهم جداً / مهم / متوسط / عادي / غير مهم) — خاص بالمدير.
- زر **عرض** يفتح التقرير كاملاً بالتفاصيل والصور، وزر **طباعة** للتقرير.
- **عوامل تصفية**: بتاريخ محدد أو من تاريخ إلى تاريخ، أو حسب اسم المستخدم، أو حسب تقييم التقرير.

### 5) تقييم المستخدمين (المدير)
- رقم التقييم، اسم المستخدم، التاريخ.
- تقييم الموثوقية / المصداقية / دقة التقرير / مدى الالتزام بتسليم التقارير
  (قوائم منسدلة قابلة للكتابة: عالية - متوسط - منخفض).
- نقاط القوة ونقاط الضعف (حقول كبيرة لعدة نقاط).
- مستوى الإنجاز (ممتاز / جيد / متوسط / مقبول / ضعيف) — حقل كتابة.
- حالة المستخدم (نشط / متقطع / غير نشط) — قائمة منسدلة قابلة للكتابة.
- **فرز وتصفية**: بالتاريخ، المستخدم، الحالة، الموثوقية، والترتيب.

### 6) الإعدادات (المدير)
- خيار استهلاك صلاحية الإضافة بعد المزامنة.
- عنوان الشبكة للأجهزة الأخرى.
- نسخة احتياطية / استعادة JSON.
- إعادة ضبط المصنع.

## 📁 بنية المشروع

```
نظام-التقارير/
├─ server.js          # الخادم (Node.js + SQLite — بدون تبعيات خارجية)
├─ run.bat            # تشغيل Windows
├─ run.sh             # تشغيل Linux / macOS
├─ README.md          # هذا الملف
├─ public/
│  ├─ index.html      # نقطة البداية (توجيه للدخول)
│  ├─ login.html      # تسجيل الدخول
│  ├─ admin.html      # لوحة المدير
│  ├─ entry.html      # صفحة إدخال البيانات
│  ├─ css/styles.css  # التنسيقات
│  └─ js/
│     ├─ app.js       # أدوات مشتركة واتصال بالخادم
│     ├─ login.js     # منطق الدخول
│     ├─ admin.js     # منطق لوحة المدير
│     └─ entry.js     # منطق الإدخال والمسودات والمزامنة
└─ data/
   └─ system.db       # قاعدة البيانات (تُنشأ تلقائياً عند أول تشغيل)
```

## 💾 النسخ الاحتياطي
- من تبويب **الإعدادات ← تنزيل نسخة احتياطية** تحصل على ملف JSON يضم المستخدمين
  والتقارير والتقييمات والإعدادات.
- **استعادة من ملف** تعيد كل البيانات.
- ⚠️ انسخ ملف `data/system.db` ضمن نسختك الاحتياطية الدورية، وهو ملف واحد سهل النسخ.

## 🔒 ملاحظات أمنية
- النظام مصمم للاستخدام الداخلي داخل شبكة موثوقة (مكتب / مؤسسة).
- كلمات المرور مخزنة مشفرة SHA-256 مع Salt.
